	\question \emph{(Verifiable pattern matching.)}

	In this problem you will construct a sumcheck-based protocol for verifiable pattern matching with wildcards. The protocol is based on a (non-cryptographic) randomized fingerprinting technique due to Adam Kalai, ``Efficient pattern matching with don't-cares'' (SODA 2002).

	\heading{Setup} Let $\F$ be a finite field.  A \emph{text} is a vector $T \in \F^N$ with $N = 2^n$.  A \emph{pattern} is a vector $P \in (\F \cup \{*\})^m$ with $m = 2^\ell$ for some $\ell \leq n$, where $*$ denotes a \emph{wildcard} that matches any field element.  We say $P$ \emph{matches} $T$ at position $j$ (for $0 \leq j \leq N - m$) if for every $i \in \{0, \ldots, m-1\}$, either $P_i = *$ or $T[j+i] = P_i$.


	\heading{The Kalai fingerprint} Given $T$ and $P$, the following randomized test checks whether $P$ matches $T$ at any position. First, compute the vector $\vecr\in\F^m$ using the rule that $\vecr_i = 0$ if $P_i = *$ and $\vecr_i \getsr \F$ otherwise.
	Compute the \emph{pattern fingerprint} $t = \sum_{i\in\{0,\ldots,m-1\}:\, P_i \neq *} \vecr_i \cdot P_i$. Then, for each position $j$, compute the fingerprint $s(j)$ as
	$$
		s(j) \;=\; \sum_{i=0}^{m-1} \vecr_i \cdot T[j+i]\,.
	$$
	Output \textsf{match} if $s(j) = t$ for any $j$ and \textsf{mismatch} otherwise. (It is not needed for this problem, but a beautiful fact about the Kalai fingerprint is that $s(j)$ can be computed for all $j$ in only $O(N\log m)$ field operations by expressing the vector of $s(j)$s as the convolution of the text and $\vecr$.)

	\question \emph{(Lariat: a lookup argument from log-derivatives.)}

	A \emph{lookup argument} lets a prover convince a verifier that every entry of a vector $\vec{a} \in \F^m$ appears in a \emph{table} $\vec{t} \in \F^N$ (where all table entries $t_j$ are distinct).  In this problem you will analyze and then build Lariat, a lookup argument based on log-derivatives.

	\heading{Setup and main idea}  Let $\vec{t} = (t_1, \ldots, t_N) \in \F^N$ with all $t_j$ distinct be a table, and let $\vec{a} = (a_1, \ldots, a_m) \in \F^m$ be a lookup vector.  A \emph{multiplicity vector} for $\vec{a}$ with respect to $\vec{t}$ is a vector $\vec{e} \in \Z_{\geq 0}^N$ where $e_j = |\{i \in [m] : a_i = t_j\}|$ counts how many times each table entry appears in $\vec{a}$.

	The key algebraic observation behind Lariat is the following.  If every $a_i$ lies in $\vec{t}$ and $\vec{e}$ is the correct multiplicity vector, then the \emph{log-derivative equation}
	\begin{equation}
		\sum_{i=1}^{m} \frac{1}{a_i - r} \;=\; \sum_{j=1}^{N} \frac{e_j}{t_j - r} \tag{$\star$} \label{eq:logderiv}
	\end{equation}
	holds as an identity of rational functions in $r$.  Conversely, as you will show below, if the lookup relation fails then~\eqref{eq:logderiv} holds for at most $m + N$ values of $r \in \F$.  So checking~\eqref{eq:logderiv} at a random $r \getsr \F$ (with $r \notin \{a_1,\ldots,a_m\}\cup\{t_1,\ldots,t_N\}$) is a sound randomized test for the lookup relation.  For parts~(b) and~(c), you may assume either that $\mathrm{char}(\F) > m$ or, equivalently, that multiplicities are interpreted as elements of $\F$ and ``incorrect'' means unequal in $\F$.
